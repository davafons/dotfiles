# Hillclimb

Read [Playbook runtime](../references/playbook-runtime.md) before executing these steps.

Select each delegate's reasoning level and speed per [dav-mode's Subagents rules](../SKILL.md#subagents), using only controls the current harness actually supports.

**You own the metric and the experiment's integrity. Supervise and review. Delegate the attempts.** For sustained, iterative improvement of one measurable thing against a target. A one-off fix is Bug fix or Perf issue. This is the loop.

Core discipline: one change, one measurement, keep or revert. Never stack untested changes, and never claim a win from code inspection (the [prove-it-works principle](../../principle-prove-it-works/SKILL.md)).

1. Ground the workload and architecture before choosing the metric. Run the **how** skill over the target, name the realistic workload dimensions that can move the result (data size, history, state, concurrency), and select a case that reproduces the user's complaint. If no case reproduces it, fix the repro instead of hillclimbing. Then fix one metric, the direction that counts as better, and a checkable stop predicate that pairs a target with a floor on attempts so a lucky early win can't end the run (the example "at least 50% better than baseline and at least 10 iterations" is this shape). Use the user's numbers when given, otherwise agree them.
2. Build the measurement harness, prove its sensitivity, then freeze it (the [build-the-lever principle](../../principle-build-the-lever/SKILL.md)). Run contrasting realistic workloads and confirm the target case reproduces the symptom while easier cases separate as expected. If the harness cannot distinguish them, revise the workload or metric. Vet the harness with the [benchmark-checklist skill](../../benchmark-checklist/SKILL.md) before you freeze it, and make it print its error count and a count of the work done. Once frozen, one repeatable command emits the metric, sampled enough to clear the noise (median of N, not a single run). Record the baseline metric and a green run of the regression gate (the tests that must keep passing) before any change.
3. Open the canonical `decisions.tsv` via the [show-me-your-work skill](../../show-me-your-work/SKILL.md), which owns its format and logger. Keep a separate `attempts.tsv` with one row per attempt and these fields: id, hypothesis, change, before, after, delta, tests, verdict (kept or reverted), note. Each canonical decision row names the attempt id and change, explains the choice, points to `attempts.tsv` and the matching id as evidence, and records the same kept or reverted result. Read both records before each attempt. Keep both local artifacts outside jj snapshots in an external per-run directory such as `~/.cache/davstack/runs/<task-slug>/`. Record both paths.
4. Ground each hypothesis in the architecture model from step 1, so it names a specific mechanism ("defer X off the boot path because it blocks first paint"), not "try memoizing something". For a perf metric, order hypotheses by the performance mantras in step 2 of the Perf issue playbook ([perf-issue](perf-issue.md)). Borrow only their order, not that step's stop rule.
5. Loop, one hypothesis per iteration:
   - Hand the change to a subagent using your configured hillclimb model with a tight scope. Supervise and review the diff rather than typing it (the [guard-the-context-window principle](../../principle-guard-the-context-window/SKILL.md)). When several independent hypotheses are live, fan them to parallel subagents, each in its own worktree (the [separate-before-serializing-shared-state principle](../../principle-separate-before-serializing-shared-state/SKILL.md)).
   - Measure before and after with the frozen harness, and run the regression gate.
   - Accept only when the metric moves past noise and the gate stays green. Otherwise revert the change in full. A tweak that "might help" is not kept.
   - One scoped change per accepted fix, using the repository's native change operations. Preserve unrelated work in a shared checkout; never include all shared edits as your own. Append the complete experiment row to `attempts.tsv`, then use the canonical logger to append its decision to `decisions.tsv`. Record matching verdicts either way, kept or reverted.
   Each iteration ends in a check before the next begins (the [sequence-verifiable-units principle](../../principle-sequence-verifiable-units/SKILL.md)). If the run is unattended, use an available, authorized scheduler for the wake mechanism, not a different stop rule. Report a missing scheduler rather than claiming the run will continue after the session ends.
6. Push past the first plateau. On a stall, several rejects in a row, pivot category, combine near-misses, re-read the source, or try something more radical before concluding the hill is climbed. Correctness and simplicity outrank the number. Revert a win that breaks behavior, and keep a simplification that holds the number (the [laziness-protocol principle](../../principle-laziness-protocol/SKILL.md)).
7. Stop when the predicate is met, or when the remaining ideas are marginal and not worth their cost. Don't relax the predicate to meet it, and don't quit while cheap untried hypotheses remain. If you are stuck, surface it instead of spinning.
8. Complete the [PR handoff](../references/playbook-runtime.md#pr-handoff) with the accepted commits stacked in the order they landed.

**Reply:** the metric and target, baseline to final with the percent delta, iterations run (kept vs reverted), each accepted fix on one line, the `decisions.tsv` and `attempts.tsv` paths, and the best idea you would try next if pushed further.
