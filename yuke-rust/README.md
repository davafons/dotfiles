# yuke-rust

Personal profile for Rust Yuke. Stow links `.config/yuke-rust` into `~/.config/yuke-rust`.

Native source is `~/workspace/yuke`, branch `davafons/rust-plugins`: one commit with the core API changes this profile needs, on top of upstream `main`.
`docs/personal-plugins.md` in that checkout documents those operations.
The SDK and installed release are in `~/.local/lib/yuke-rust`.
`~/.local/bin/yuke` and `~/.local/bin/yuke-rust` both run it with `YUKE_APPNAME=yuke-rust`.

## Install

```sh
make install PROFILE=mb
```

That stows this package and runs `scripts/setup-state.py`.
The state step creates only what is missing and never replaces existing files.

## What dotfiles owns and what stays live

Linked from dotfiles (settings you edit):

| Path | Contents |
| --- | --- |
| `config.json` | Plugin list and plugin options, including `startupModel` and `startupEffort` for the models plugin |
| `providers.json` | Custom providers and model metadata. It holds no credentials |
| `plugins/*`, `helpers/*`, `*.ts` | Plugin and helper sources |
| `plugins/personal/prompt.json` | Personal system prompt |

Yuke writes `config.json` and `plugins.lock` through the link when the plugin manager changes them, so the target in dotfiles stays current.

Live only (state or secrets, never in the repository):

| Path | Why |
| --- | --- |
| `~/.config/yuke-rust/monid.key` | Web plugin secret. Copy it by hand on a new machine. `**/*.key` is ignored |
| `~/.config/yuke-rust/tsconfig.json` | Generated by the state step with the absolute SDK path |
| `~/.local/share/yuke-rust/auth.json` | Logins and stored API keys. Yuke writes it with mode 0600. The state step creates an empty one |
| `~/.local/share/yuke-rust/yuke.db`, `sessions/` | Chat store |
| `~/.local/share/yuke-rust/plugins/<name>/` | Plugin data: task and inbox databases (created on first use), model aliases (seeded from `state/model-aliases.json`, then edited in the app), search index, prompt history |

Skills come from `~/.agents/skills` and the workspace's `.agents/skills`. Global instructions come from `~/.agents/AGENTS.md`. Both are in the `agents` package.
There is no `~/.config/yuke-rust/mcp.json`. Shared MCP servers are in `~/.mcporter/mcporter.json` and are reached through the mcporter skill.

## Verify

```sh
python3 ~/dotfiles/yuke-rust/scripts/verify.py --source ~/workspace/yuke --binary ~/.local/lib/yuke-rust/bin/yuke
```

Add `--native` to also run the native workspace checks.
The checks include TypeScript, Biome, the plugin-host tests, the Vim tests, the Python store tests, a real terminal check in a private profile that syncs its Git plugins, and `tests/check-agent-tools.py`, which routes the four agent roles through `yuke --rpc` against a scripted local provider.
The terminal check makes no model requests and uses no real credentials.
`make doctor PROFILE=mb` checks that the profile is linked, that no link dangles, and that tracked files hold no secrets.

## Update the native build

```sh
cd ~/workspace/yuke
mise exec -- python3 tools/package.py --nightly
python3 ~/dotfiles/yuke-rust/scripts/install.py --source "$PWD" --archive target/packages/yuke-aarch64-macos.tar.gz --activate
```

The installer verifies the candidate, saves a versioned release in `~/.local/lib/yuke-rust-releases`, then moves the public link.
A changed native binary needs a restart. A profile change needs `/reload` while idle.

## Plugin manager

A string such as `"./plugins/dashboard"` in `config.json` loads a local folder relative to that file.
An object with `path` can also supply `options`.
A Git-managed plugin uses a repository URL and a folder:

```json
{ "git": "https://github.com/lostcoords/yuke-plugins", "folder": "plugins/btw", "ref": "main" }
```

`plugins.lock` records the exact commit. `yuke plugin add URL --folder plugins/btw` adds one, `yuke plugin sync --locked` restores the lock, and `yuke plugin update --all` asks before changing it.
